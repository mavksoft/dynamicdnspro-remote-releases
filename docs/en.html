What it is

DDNSPro Remote is the remote-access product of the Dynamic DNS Pro ecosystem — separately licensed, sharing your account, machines and permissions with the web portal. Install the host on the machines you manage, then reach them from the native macOS viewer or any browser: desktop, files, console and power actions over end-to-end-encrypted WebRTC.

Features

WebRTC P2P sessions — low-latency desktop video, audio and input with DTLS encryption end to end.
Consent-based access — the remote side approves each session, or grant permanent/reconnect allowance per machine.
File manager — browse remote drives, drag-and-drop uploads and downloads inside the session.
Machine lobby — account machines with live thumbnails, or ad-hoc connections by ID + password.
RDP session picker — on multi-session hosts, choose an existing session or open a new one.
Resolution control — switch the remote display resolution in-session (admin profiles).
Wait-for-reconnect — reboot the remote machine and the session reattaches on its own.
Power actions — reboot, lock, Ctrl+Alt+Del / SAS, Win+D from the session bar.
Signed auto-updates — Ed25519-signed manifests; macOS builds notarized by Apple.
Six languages — ES / EN / FR / IT / DE / PT.

How to use it

  1. 1Sign up at dynamicdnspro.com and enable a Remote plan.
  2. 2On each machine you want to reach, install the Windows Remote host — it registers under your account with a machine ID.
  3. 3Set the access policy per machine: consent every time, always allow, or allow with reconnect grace.
  4. 4Open the macOS viewer (or the web lobby) and sign in — your machines appear with live status.
  5. 5Click a machine → session opens: desktop, files and power actions in one window.

Requirements

macOS 12+ for the native viewer · Windows 10/11 for the remote host · Every release ships .sha256 checksums for all binaries.

FAQ

Is the traffic encrypted?

Yes — sessions run over WebRTC with DTLS-SRTP; signaling travels over authenticated TLS. Consent and policies are enforced host-side, so failed authorization fails closed.

Do I need a Dynamic DNS Pro subscription?

Remote is licensed separately — you can buy it on its own. If you already have an account, it shares your login and machine list.

Viewer vs host — what's the difference?

The viewer (this repo) is what you run to connect; the host (in dynamicdnspro-releases) is what runs on the remote machine.

Can I connect without an account?

Yes — ad-hoc sessions work with the remote machine's ID and password, like classic remote-assistance tools.
